# SOC Log Investigation

This project is a defensive, end-to-end security-operations-centre (SOC) investigation of a
synthetic authentication log for the **NoteShare** student notes-sharing platform. It was
created as an authorised, local-only lab exercise using fictional accounts and
documentation-range IP addresses (RFC 5737: 192.0.2.x, 198.51.100.x, 203.0.113.x). No
external systems were contacted at any point.

## Key Findings

All statistics below are computed in `investigation.ipynb`.

1. **Brute-force account compromise** — Attacker IP `192.0.2.10` made **25 consecutive login
   failures** against account `jsmith` between 02:00–02:29 UTC, then succeeded at 02:35 UTC,
   indicating the account password was successfully cracked.

2. **Password-spray campaign** — IP `198.51.100.50` fired **20 failure events across 15
   distinct accounts** in a 42-minute window (03:00–03:42 UTC), with ≤ 2 attempts per account
   — a classic low-and-slow spray pattern designed to evade per-account lockout policies.

3. **Privileged account accessed from new IP during off-hours** — `admin_user` authenticated
   successfully at 03:50 UTC from `198.51.100.51`, an IP never previously seen in the log for
   that account and outside normal business hours (00:00–05:59 UTC), raising a high-severity
   concern about admin credential compromise.

4. **Data-quality issues resolved before analysis** — Of 473 raw rows, **2 fully empty rows**,
   **2 invalid-IP rows**, and **3 exact duplicates** were removed, yielding **465 clean events**
   (104 failures, 361 successes) used for all detection and reporting.

5. **Normal traffic dominates daytime hours** — 361 of 465 success events (≈78 %) occur
   between 08:00–18:00 UTC from internal `10.0.0.x` IPs, confirming that the overnight
   activity (02:00–03:50 UTC) is anomalous and attributable entirely to the three attacker IPs.

## Detection Rule Thresholds

| Rule | Threshold | Rationale |
|------|-----------|-----------|
| Brute Force | ≥ 10 failures, 1 account, 1 IP, 60-min window | Well above normal typo rate (1–3/hr) |
| Password Spray | 1 IP → ≥ 8 distinct accounts, ≤ 3 attempts each, 60 min | Distinct targets signal spray not brute |
| Off-hours Privileged Login | Privileged account success 00:00–05:59 UTC | Students/staff unlikely active overnight |
| New IP for Privileged Account | First-ever IP for admin/root/sysadmin success | Unexpected location = elevated risk |
| Success After Failure Streak | ≥ 5 consecutive failures then success | Persistent trial suggests credential attack |

---

## Recommended Actions (from report)

1. **Lock** `jsmith` and `admin_user` accounts immediately; force password resets for all 15
   spray-targeted accounts.
2. **Block** attacker IPs at the perimeter firewall: `192.0.2.10`, `198.51.100.50`, `198.51.100.51`.
3. **Enforce MFA** for all privileged accounts and any account logging in from a new IP.
4. **Rate-limit** login attempts at Nginx/Express: ≤ 5 per minute per IP with exponential back-off.
5. **Add SIEM rules** mirroring the detection thresholds above with automated incident ticketing.
